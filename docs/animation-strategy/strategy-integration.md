# Whole-roster integration strategy

Read-only fourth planning review, September 7, 2026. Inspected the uplift scope, all 64 animal profile rows, mesh renderer, render pose pipeline, simulation, ground motion, save validation, relevant existing natural-history entries, and the propulsion and reef-agent plans. The residents plan was not yet available. No original-game research or runtime edits were performed.

## Assessment

The current prototype is an engine foundation, not a completed roster uplift. Its largest integration risk is that **declared coverage and reachable behavior are different things**. `animal-profiles.js` lists 64 routines and social preferences, while `simulation.js` still uses the older `behaviors.js` with six social profiles and three adventure routines. A profile row cannot substantiate an implemented routine.

The current bottom-resident branch walks along a route, opportunistically eats a nearby item, then returns. It never selects an accessible meal destination, and does not set the feeding action envelope consumed by the new renderer. The holdfast seahorse returns before any feeding logic. A stationary anemone can consequently be beautifully animated but have no observable capture loop. These are concrete examples of why every species needs an actual simulation trace and motion review.

Other important gaps:

- The mesh receives movement effort, feed and retraction, but not brake, coast, turn effort, contact, rest or departure. The older `poseFor` still applies a whole-body feeding squash despite the new mesh's promise to protect anatomy.
- Generic feeding animation begins when `consume` removes food. There is no anticipation phase, so the mouth action can visibly happen after the meal disappears. NPC bottom feeding does not set `actionTime` at all.
- Center-to-center feeding reach ignores snouts, underside ray mouths, anchored anemone crowns and ground paths. A distant food marker can be inside an entity's nominal diet and still be unreachable in its movement domain.
- `activity` resets to cruising at each NPC update, while longer avoidance behavior is inferred from English text. This can overwrite an activity before the visual pose has had time to settle. Structured durable intent should own the display text, rather than text owning intent.
- Render poses are keyed by entity ID. Player replacement clears the map, but an NPC's death/respawn keeps its ID and can retain a stale smoothed facing or movement sample. Scene transitions can produce a false high-effort first frame from discontinuous coordinates.
- Absolute mesh cache ticks plus individual phases cause repeated canvas allocation and 144–192 clipped image draws on a miss. A bounded cache is necessary but does not prove acceptable frame time.
- Existing natural-history limitation paragraphs will become stale as behaviors are added. Update only claims whose implementation has passed review; leave identification and authored simplification limits intact.

## One behavior-to-animation contract

Make the simulation authoritative for **what the animal is doing**, and the renderer authoritative for **how that action looks**. Keep these responsibilities separate without allowing them to drift.

Suggested simulation state:

```
intent: cruise | forage | evade | clean | social | return | rest
routine: { kind, phase, timer, siteId?, partnerId?, hostId?, targetId? }
action: { kind, phase, elapsed, duration, contactCommitted }
movement: { desiredSpeed, speed, turnEffort, coast, attachment? }
```

The names are an implementation suggestion, not a required schema. A shared decision order should be explicit: dead/stunned → invalid-state cleanup → immediate safety → existing cleaner protocol → committed valid feeding contact → normal food approach → social/local routine → neutral cruise/rest. Do not run another routine after a higher-priority branch has claimed the animal. Player steering must cancel optional pose transitions promptly; do not add animation locks to mouse movement.

Use a single action sequence for ordinary meals: **approach and brake → anticipatory mouth/appendage pose → contact and resource mutation → short recovery → resume intent**. The contact phase performs consumption exactly once, with a last validity/range check. An interrupted anticipation must not award a meal. A canceled recovery may leave the food consumed but must not consume it twice. Actions should be observable in paused inspection and readable at gameplay size.

Keep locomotion cycle phase continuous while speed changes. Separate its phase from amplitude, so a coast can reduce tail drive without snapping to another sine position. Distinguish passive current motion from active propulsion and contact motion. A breathing or tentacle loop does not imply locomotion. Root translation, turn banking and protected head pose should be cheap transforms; expensive local deformation should depend on compact phase/state bins.

The same semantic action drives a fish's jaw, a ray's underside contact, a crab's claws, a seahorse's snout, and an anemone's inward tentacle curl. Do not force the same geometry or timing on them.

## Attachment, food and population integration

Introduce explicit movement domains: free water, near-bottom, a specific ground route, a refuge contact point, or a live/fixed holdfast. A local routine can temporarily leave an attachment only if its body plan allows that transition. NPC ray and flathead near-bottom travel differs from a snail's ground path and from an anemone's fixed base.

Food queries must include domain reachability, not only diet and radial distance. For a route resident, project a candidate onto its route and reject an incompatible distant patch; then walk to the contact point rather than follow the generic fish steering. A fixed feeder needs a suitable passing food/contact resource within reach. Preserve the current amount/regrow economy unless a deliberately documented local resource is necessary. Never make decorative drifting plankton quietly supply unlimited energy.

Use transformed anatomical contact anchors for presentation and final reach tests. Keep forgiving hit targets for the child's mouse input. Click selection can remain generous while the animal approaches a visually credible contact point. The large ray's contact point belongs under its disc; needlefish/trumpetfish mouth contact belongs at the end of the snout. A goby's home or crab's foot must not slide while the renderer adds feeding pitch.

Social breadth at today's modest densities needs composition work, not merely more logic. Existing random rosters may seldom provide two individuals of a newly paired species. Prefer compatible groupings within existing forager/companion slots, preserving count distributions and habitat variation. Keep solitude visible, too. Test actual naturally populated scenes where each chosen interaction can occur; a developer-injected five-fish school is useful engineering evidence but insufficient delivery evidence.

## Performance and lifecycle design

- Replace absolute-tick reusable mesh keys with a bounded cyclic phase, a few meaningful effort tiers, size tier, rig identity and a limited action/transition state. Multiple independent frequencies in one deformation field must share a deliberate repeat period, or be evaluated as separate layers; moduloing a nonperiodic function will introduce seams.
- Separate repeating neutral/swim frames from one-shot action frames. Avoid multiplying every movement bin by every possible action. Benchmark both a cold scene and a warmed scene before choosing precompute versus lazy fill.
- Use fewer mesh subdivisions and lower deformation cadence for small/background NPCs. Keep player, inspected animal and nearby actions at full quality. Loops may be 12–24 Hz while root movement remains frame-rate smooth. Paused and reduced-motion modes should not continue warming caches for invisible motion.
- Cache memory should include backing RGBA pixels and frame count, plus observations of process memory. Current 12M cached pixels imply approximately 48 MiB of raw pixel storage before browser canvas overhead. Rendering a tint as a second deformed image can double work during camouflage.
- Clear transient render poses on respawn and discontinuous section changes; prune absent entities. A persistent NPC ID is not proof that its current pose is continuous. Handle hidden/collapsed pages without replaying a giant elapsed-time transition.
- Persist only meaningful simulation state: selected site/partner, action contact ownership, attachment and relevant timer. Never serialize canvas caches. Preserve or reconstruct cycle phase without RNG changes; validate finite timers, known state names, same-section live relationships, and valid attachment paths on import.
- Compatibility defaults must reach a valid neutral routine. Ground routes already have a validator, but imported animal validation currently does not apply it. Validate new attached state rather than allowing malformed arrays to reach placement math.

## Sequence that respects the larger scope

1. **Establish evidence before extending:** preserve current Windows ZIP, record current population/harm traces, frame-time distributions and ordinary gameplay videos. Create a 64-row coverage ledger with every entry unaccepted initially. Record current prototype shortcomings rather than counting profiles as completed.
2. **Build the shared contract and representative rigs:** integrate approach/contact/recovery, acceleration/coast/braking, anatomy contact points, bounded cache and attachment frame. Use s2, s23, s4, s20, s26, s27, s41, s44, s46 and s63 to expose incompatible body plans. These are engineering probes, not the final scope.
3. **Complete all rig families and all 64 profiles:** author actual cropped-sprite anchors, protected regions and appendage paths. Use the three species-agent plans as work lists. Every profile needs a visible distinguishing action or movement signature; duplicated engines are fine, anonymous defaults are not acceptance.
4. **Integrate the eight ecological systems:** retire the disconnected old-profile source, assign supported routines to all 64, validate domain feeding, and make population composition expose meaningful interactions without raising density. Update observation/status text from structured states so the family can notice what happened.
5. **Review by complete groups, then ordinary game:** capture both facing directions and state transitions at gameplay and inspection sizes, fix a batch and confirm once. Keep any species with unresolved art/anatomy problems explicitly open. Then play normal scenes demonstrating the systems at both target viewport sizes.
6. **Only then delivery:** run combined regression/performance/native Windows checks, finish the ledger and source limits, package one combined build and verify archived bytes. Do not describe a family prototype or passing generic test as a full-game polish.

## Acceptance ledger and evidence standard

Each of the 64 rows should link to: rig/motion identity; sourced versus authored routine; actual gameplay spawn path; cruise/idle/turn/feed/rest/departure visual evidence; an interruption case; ordinary-game interaction evidence; anatomical issues; acceptance status. Non-playable animals still need motion, feeding/contact and interaction evidence. Static sea stars/anemones are not exempt from being visibly alive, but must not be forced into fish locomotion.

For each species, inspect a short motion strip/video at ordinary size and enlarged inspection size, both facings. Record whether the eye, mouth, protected torso, rigid shell/horns/spines, appendage roots and ground contact stay coherent. A still contact sheet can find clipping or wrong anchors, but cannot prove smoothness, timing or life. A scripted gallery is controlled evidence; also record genuine in-game behavior for the full roster in staged ordinary scenarios, and naturally composed scenes for each social system.

Behavior tests should prove consequences and lifecycle, not just labels: a pair remains associated after feeding; a school re-forms without overlaps; a host resident departs and returns; a bottom animal obtains a reachable meal; a fixed feeder captures without sliding; a canceled strike does not consume; death invalidates social targets; save/restore during contact neither duplicates nor loses consumption. Measure deterministic traces and reference validity across travel, respawn, save import and extended runtime.

Broad invariants: modest population counts and variation, no new cleaner predation, bounded threat pursuits, responsive mouse/E/Space/C inputs, readable player marker, no automatic guide narration, pause freezing all relevant motion, reduced-motion static action cues, legacy saves, and Windows-only delivery. These must be checked with the integrated build, not inferred from an earlier archive.

Performance evidence should record p50/p95/p99 frame time, long frames, cache misses/hits/bytes, and process memory in both 1600×900 and 1024×768; include the title, ordinary mixed reef, largest animals, feeding/camouflage activity, scene travel and cold caches. Choose an explicit playable target and compare to the measured baseline; do not call average FPS alone a proof of smoothness. Report hardware and headless/native distinction.

The completion claim should state exactly which roster rows were visually reviewed and which real interaction scenarios passed. If an anatomy/art dependency remains—especially the coiled moray or a clipped narrow appendage—the honest status is unfinished for that row. The standard is the requested observable whole-roster uplift, not a green count produced by a narrower test suite.
